# AI-Driven DevOps Monitor & Auto-Healer

Система предиктивного мониторинга и автоматического восстановления ИТ-инфраструктуры (Auto-Healing). Проект в реальном времени собирает метрики производительности контейнеров, сохраняет их в Time-Series БД InfluxDB, использует алгоритм машинного обучения *Isolation Forest* для выявления аномальных всплесков нагрузки и автоматически перезапускает дефектные сервисы через Docker API хоста.

## Схема взаимодействия модулей


**Поток данных:** `agent` непрерывно пишет системные метрики хоста в `InfluxDB`. Модуль `brain` анализирует скользящее окно истории на предмет аномальных векторов признаков. При обнаружении угрозы отправляется локальный вебхук в сервис `notifier`, который мгновенно сбрасывает аварийный контейнер `leaky-app`, предотвращая деградацию всей инфраструктуры.

## Механизмы отказоустойчивости (Fault Tolerance)
1. **Network Resilience (Агент):** Логика записи метрик обернута в блоки обработки исключений. При временной недоступности базы данных агент не завершает процесс, а уходит в безопасный таймаут и циклически повторяет попытки реконнекта.
2. **Anti-Flapping / Rate Limiting (Нотификатор):** Защита от лавинных перезапусков контейнера при циклической критической аварии (*Bootloop*). Модуль ведет учет истории инцидентов через двустороннюю очередь `deque`. При превышении лимита в 2 рестарта за 15 минут автоматика блокируется и требует ручного вмешательства инженера.
3. **Resource Isolation (WSL2 / Docker Host):** Настройки ядра подсистемы распределения ресурсов изолируют тестируемый контейнер `leaky-app`, гарантируя стабильную работу ядра мониторинга (БД, ИИ, логика сброса) даже при 100% утилизации ресурсов целевого приложения.

## Что за что отвечает

| Сервис (контейнер) | Файл | Ответственность |
|---|---|---|
| **influxdb** | `influxdb:2.7` | Time-Series БД. Хранит историю временных рядов метрик. |
| **agent** | `agent/agent.py` | Раз в 5 сек собирает CPU, RAM, диск, число процессов хоста и пишет в базу. |
| **brain** | `brain/brain.py` | Раз в 10 сек анализирует тренды. Содержит гибридный слой: ИИ-алгоритм (*Isolation Forest*) + жесткий предиктивный порог безопасности на 60%. |
| **notifier** | `notifier/notifier.py` | Flask-сервер оркестрации. Принимает триггеры, управляет контейнерами через смонтированный сокет `docker.sock` и логирует события. |
| **leaky-app** | `leaky-app/leak.py` | Тестовое приложение для демонстрации утечек памяти. |

## Как запускать

Все команды выполняются из корня проекта. Файл настроек `.env` создается локально на базе шаблона `.env.example` и скрыт из публичного репозитория через `.gitignore`.

| Действие | Команда |
|---|---|
| Собрать и запустить всю инфраструктуру в фоне | `docker compose up --build -d` |
| Проверить статус работы всех 5 микросервисов | `docker compose ps` |
| Посмотреть живые логи конкретного модуля | `docker compose logs -f <имя_сервиса>` |
| Запустить симуляцию лавинообразной аварии памяти | `docker compose exec leaky-app python leak.py` |
| Остановить систему с сохранением данных базы | `docker compose stop` |
| Полностью уничтожить контейнеры и очистить тома | `docker compose down -v` |

## Порядок проверки автохилинга (Демонстрация)

1. Разверните стек: `docker compose up --build -d`. Убедитесь в Docker Desktop, что все 5 контейнеров перешли в статус `Running`.
2. Запустите скрипт утечки памяти внутри изолированного окружения:
   ```bash
   docker compose exec leaky-app python leak.py
   ```
3. Откройте вкладку **Logs** контейнера `brain-1` или `notifier-1`. 
4. При достижении критического вектора нагрузки ИИ перехватит инцидент, залогирует аварийный статус (`🔴 [CRITICAL] RAM crossed 60% threshold / 🚨 ANOMALY DETECTED!`) и принудительно перезагрузит `leaky-app`, мгновенно вернув ресурсы системе.
